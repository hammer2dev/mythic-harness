# 环境与 Agent 应用

桌面窗口的「环境」位于「插件市场」和「模型网关」之间。进入后显示二级页「Agent应用」。本机用户的应用配置在各项目间共用。普通 Web 和手机远控不发布管理入口或应用执行服务。

## 管理流程

- 同一张表按「已安装」「未安装」分组，搜索同时匹配两组。目录包含 Codex、Claude Agent、Kimi Code、Gemini CLI、OpenCode，以及用户接入的自定义 ACP。扫描识别本机启动程序。发现程序后仍需用户接入。内置应用可使用发现的程序或指定路径，自定义 ACP 保存名称、启动程序和逐行填写的参数。
- 页面标题右侧依次显示搜索、「扫描本机」和「接入应用」。空间充足时同排显示，窄窗口按内容宽度换行。
- 表格显示应用、本机程序、最新版本、启用和居中的图标操作。可用的已接入应用提供修改、模型管理、测试与更多菜单。应用名称打开详情。最新版本大于本机版本时显示升级入口。应用详情可查看程序路径、已选模型和最近 20 条测试结果，包含回复或失败原因。
- 首次加载使用实际表头和对齐的占位行，读取成功后原位显示数据。手动读取模型时，按钮显示旋转图标和「读取中…」，已显示的候选仍可查看，请求结束后恢复按钮。添加或启停模型时，读取按钮保留原文案。
- 切换应用开关、编辑路径或参数、添加或启停模型都自动保存。模型读取更新当前候选并保留已有选择。测试仅选择当前候选中的已启用模型，返回所选模型、回复、耗时或失败原因。没有可用模型时从测试弹窗进入模型管理。测试可取消，使用独立进程、临时目录和固定短提示。
- 升级和卸载可在原 npm 安装目录执行。其他来源显示由原安装渠道维护。升级成功后重新探测版本，清除当前候选和测试状态，保留应用开关、已选模型和测试历史。卸载成功后关闭应用开关，保留已选模型和历史以便重新接入。移除接入删除配置并保留本机程序。更换程序或启动参数后需要重新读取候选。

## 保存与运行边界

桌面 Local Host 的 Agent 应用服务是唯一写入方。配置使用 ZCode 用户数据目录下的 v2/agent-applications.json，带格式版本。保存稳定应用 ID、程序路径、来源、版本、开关、启动参数、模型选择和测试摘要。模型提供方的登录继续由对应 Agent 处理。

```text
桌面界面 → 本机 Host 服务 → 独立命令与校验 → 锁内读取最新 JSON → 原子替换 → 返回结果
                                │
                         选择的程序与模型 → 独立诊断进程 → 回复或错误
```

长操作按应用串行。一次程序更新完成后再提交该应用的设置，其他应用的设置继续独立保存。取消或失败的模型读取保留旧候选。扫描以当前程序的存在状态和版本为准。该服务与任务、会话、模型网关及 ZCode Agent 运行时独立。

加载反馈由页面 hook 按当前请求类型提供，并随请求结束消失。

```text
进入页面 → 目录请求 → 表头与占位行 → 应用列表或错误
读取模型 → 读取请求 → 按钮显示读取中 → 模型列表或错误
```

## 验收

1. 从桌面一级栏打开环境，核对分组、列、模型和更多入口。回到项目可继续打开原草稿。
2. 通过可控的本机 ACP 程序接入两个模型、启用应用、手动选择其中一个模型并收到回复。刷新、重新进入后，应用开关、路径、模型和测试记录可恢复。
3. 核对程序的更新资格、移除接入后的文件保留、卸载后的设置保留，以及无模型、请求失败或取消时的状态。
4. 暂停本机程序返回版本或模型，确认等候期间显示对应加载反馈，恢复后列表和按钮按请求结果更新。
5. 在宽窄窗口核对搜索与操作的位置，并验证搜索同时筛选已安装和未安装的应用。
