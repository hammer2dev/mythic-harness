# Coding Plan 购买入口退役

## 目标

移除应用内所有 Coding Plan 的升级、续费、购买、定价和支付引导，让通用开发 Agent 只保留开发者使用所需的连接状态、额度与用量信息。

## 行为范围

- 侧栏用量摘要不再显示升级或续费菜单项。
- 对话错误、额度不足提示和输入框上下文余额不再提供升级、续费或购买按钮。
- 设置中的 Coding Plan 状态区域只展示当前连接、登录、套餐状态、额度、用量和刷新等只读或连接管理能力；不展示选择套餐、查看价格、购买、升级、续费、充值或支付入口。
- 自动化设置中的 Coding Plan 额度提示不再触发购买弹窗；已有的额度查询和状态读取继续工作。
- 闲时任务在账号不具备资格时只提示当前账号不可用，不展示订阅、升级或续费宣传文案。
- Coding Plan 升级弹窗、购买 webview、支付流程、购买漏斗埋点及其 UI 提供者不再装配。
- 保留已购买套餐的 entitlement 查询、套餐状态、到期/重置时间、额度统计、模型连接和登录/登出能力。登录或连接失败仍可提示用户重试或连接，不改为购买引导。
- 不影响桌面应用自动更新、插件更新或普通依赖更新入口。

## 状态所有者与边界

- Coding Plan entitlement、连接和用量状态仍由现有 provider/service 与模型供应商设置状态所有者维护；UI 只通过现有 hooks/props 读取并发送连接、刷新等命令。
- 移除 `CodingPlanUpgradeDialogProvider` 及其调用方后，不新增替代状态或购买路径。
- `purchaseUrl`、产品价格查询和购买漏斗上下文仅服务购买流程；确认无调用方后删除其 UI 传递和埋点代码。只读套餐状态所需的 provider 元数据继续保留。

## 验收场景

1. 打开侧栏账户区域，菜单中没有 Coding Plan 升级或续费项，但额度摘要仍可见。
2. 触发额度不足、上下文余额不足或服务错误提示，不出现购买、升级或续费按钮，也不会打开购买弹窗。
3. 打开模型供应商设置，Coding Plan 可以登录、连接、断开并查看状态、额度和重置/到期信息；页面没有方案卡、价格、购买、升级、续费、充值和支付按钮。
4. 自动化设置仍能读取 Coding Plan 可用性和额度，失败时可重试，不会跳转购买流程。
5. 应用更新相关入口继续存在。

## 迁移与清理边界

- 先移除 UI 入口和购买弹窗装配，再依据 TypeScript 引用和导出检查清理不再使用的购买组件、状态、文案、产品数据与埋点。
- 不删除仍被只读状态、连接或额度展示使用的通用 Coding Plan 类型和查询接口。
- 不恢复或改动工作区中与本任务无关的本地新增目录。

## 验证

- 执行 `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed`。
- 对改动文件执行格式检查，并运行已有的相关 UI/组件测试；只补充覆盖上述关键入口消失与只读状态保留的最小测试。

## 底层写入契约退役边界

- `ICodingPlanSubscriptionService` 与 Coding Plan provider 不再暴露个人套餐购买预览、签约、支付状态轮询、银行卡/PayPal 支付和企业订单创建、支付、取消、续费、状态查询等写入或支付流程。
- 同步移除上述流程专用的 shared 请求/响应类型、支付方式类型、订单类型、支付 endpoint helper、支付回跳和相关 provider 常量，避免通过 RPC 或远程 Host 继续调用已下线的购买能力。
- 保留 `getEnterprisePricing`、`getStaticTeamProducts` 以及其中用于已购 Team Plan 识别的 `subscribed`、组织/项目上下文、API Key 状态等只读字段；不再将价格、折扣、续费金额或购买方式作为可操作入口。
- 保留 Off-Peak、动态工作流和其它客户端配置查询能力；这些配置与套餐购买无关。
